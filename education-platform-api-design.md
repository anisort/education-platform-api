# Education Platform API

## 1. Overview

### 1.1. Project Description

The Education Platform API provides functionality for managing educational courses and student enrollments.

The platform allows users to register as instructors or students. Instructors can create and manage their own courses, view enrolled students, and add or remove students from their courses. Students can browse available courses and view the courses in which they are enrolled.

The API follows REST architectural principles and uses JSON for data exchange.

### 1.2. User Roles

The platform supports two user roles:

| Role | Responsibilities |
|---|---|
| **INSTRUCTOR** | Creates, views, updates, and deletes own courses. Views students enrolled in own courses. Adds and removes students from own courses. |
| **STUDENT** | Registers on the platform, views available courses, and views courses in which they are enrolled. |

Each user has one role assigned during registration.

### 1.3. Main Entities

The API consists of three main entities:

- **User** — represents a registered platform user. Each user has a role that determines their permissions.
- **Course** — represents an educational course created and managed by an instructor.
- **Enrollment** — represents the relationship between a student and a course.

The relationship between `User` and `Course` is many-to-many through the `Enrollment` entity. Only users with the `STUDENT` role can be enrolled in courses.

### 1.4. Base URL

```text
http://localhost:8080/api/v1
```

### 1.5. Data Format

All requests and responses use JSON.

```http
Content-Type: application/json
```

## 2. Data Models

### 2.1. User

The `User` entity represents both instructors and students. The user's role determines which operations they can perform.

| Field | Type | Required | Description |
|---|---|---|---|
| `id` | UUID | Generated | Unique user identifier. Generated by the server. |
| `firstName` | string | Yes | User's first name. |
| `lastName` | string | Yes | User's last name. |
| `email` | string | Yes | Unique email address. Must be a valid email. |
| `password` | string | Yes | User password. Stored as a secure hash and never returned in responses. |
| `role` | string (enum) | Yes | User role: `INSTRUCTOR` or `STUDENT`. |
| `registrationDate` | string (date) | Generated | User registration date. Generated by the server. |

**Example:**

```json
{
  "id": "11111111-1111-1111-1111-111111111111",
  "firstName": "John",
  "lastName": "Smith",
  "email": "john@example.com",
  "role": "INSTRUCTOR",
  "registrationDate": "2026-11-11"
}
```

The `password` field is excluded from user responses.

### 2.2. Course

The `Course` entity represents an educational course created by an instructor.

| Field | Type | Required | Description |
|---|---|---|---|
| `id` | UUID | Generated | Unique course identifier. Generated by the server. |
| `title` | string | Yes | Course title. |
| `description` | string | No | Course description. |
| `durationHours` | integer | Yes | Course duration in hours. Must be greater than zero. |
| `instructorId` | UUID | Generated | Identifier of the instructor who created the course. Determined by the server. |

**Example:**

```json
{
  "id": "22222222-2222-2222-2222-222222222222",
  "title": "Introduction to Python",
  "description": "A beginner-friendly Python programming course.",
  "durationHours": 40,
  "instructorId": "11111111-1111-1111-1111-111111111111"
}
```

The `instructorId` field is assigned automatically based on the authenticated instructor. It cannot be specified or changed by the client.

### 2.3. Enrollment

The `Enrollment` entity represents the relationship between a student and a course.

| Field | Type | Required | Description |
|---|---|---|---|
| `studentId` | UUID | Yes | Identifier of the enrolled student. |
| `courseId` | UUID | Yes | Identifier of the course. |

**Example:**

```json
{
  "studentId": "33333333-3333-3333-3333-333333333333",
  "courseId": "22222222-2222-2222-2222-222222222222"
}
```

Each enrollment connects one student with one course.

A student cannot be enrolled in the same course more than once.

Enrollment records are created and managed by instructors.

## 3. Authentication and Authorization

### 3.1. Authentication

The API uses JSON Web Token (JWT) Bearer Authentication.

Users must register and log in to obtain an access token.

The token must be included in the `Authorization` header when accessing protected endpoints.

```http
Authorization: Bearer <access_token>
```

### 3.2. Authorization

Access to API operations depends on the authenticated user's role.

| Operation | INSTRUCTOR | STUDENT | Public |
|---|:---:|:---:|:---:|
| Register | Yes | Yes | Yes |
| Login | Yes | Yes | Yes |
| View all courses | Yes | Yes | Yes |
| View a course by ID | Yes | Yes | Yes |
| Create a course | Yes | No | No |
| Update own course | Yes | No | No |
| Delete own course | Yes | No | No |
| View students in own course | Yes | No | No |
| Add a student to own course | Yes | No | No |
| Remove a student from own course | Yes | No | No |
| View own enrolled courses | No | Yes | No |

### 3.3. Access Rules

- Public endpoints do not require authentication.
- Protected endpoints require a valid JWT access token.
- An instructor can manage only courses created by that instructor.
- An instructor can view and manage enrollments only for their own courses.
- Only users with the `STUDENT` role can be enrolled in courses.
- A student can view only their own enrolled courses.
- A user cannot change their role through course or enrollment operations.

## 4. API Endpoints

The API contains 11 endpoints divided into four groups:

- Authentication — 2 endpoints.
- Course — 5 endpoints.
- Student — 1 endpoint.
- Enrollment — 3 endpoints.

### 4.1. Authentication Endpoints

#### 4.1.1. Register a User

**Endpoint:**

```http
POST /auth/register
```

**Description:**

Registers a new user on the platform. A user can register as an instructor or a student.

**Access:** Public.

**Request Body:**

| Field | Type | Required | Description |
|---|---|---|---|
| `firstName` | string | Yes | User's first name. |
| `lastName` | string | Yes | User's last name. |
| `email` | string | Yes | Unique email address. |
| `password` | string | Yes | User password. |
| `role` | string (enum) | Yes | User role: `INSTRUCTOR` or `STUDENT`. |

**Example Request:**

```json
{
  "firstName": "Jane",
  "lastName": "Brown",
  "email": "jane@example.com",
  "password": "password123",
  "role": "STUDENT"
}
```

**Success Response:**

`201 Created`

```json
{
  "id": "33333333-3333-3333-3333-333333333333",
  "firstName": "Jane",
  "lastName": "Brown",
  "email": "jane@example.com",
  "role": "STUDENT",
  "registrationDate": "2026-11-11"
}
```

**Possible Errors:**

- `400 Bad Request` — Invalid request data.
- `409 Conflict` — A user with this email already exists.

#### 4.1.2. Login

**Endpoint:**

```http
POST /auth/login
```

**Description:**

Authenticates a registered user and returns a JWT access token.

**Access:** Public.

**Request Body:**

| Field | Type | Required | Description |
|---|---|---|---|
| `email` | string | Yes | Registered email address. |
| `password` | string | Yes | User password. |

**Example Request:**

```json
{
  "email": "jane@example.com",
  "password": "password123"
}
```

**Success Response:**

`200 OK`

```json
{
  "accessToken": "<jwt_access_token>",
  "tokenType": "Bearer"
}
```

**Possible Errors:**

- `400 Bad Request` — Invalid request data.
- `401 Unauthorized` — Invalid email or password.

|---|---|---|---|

| Field | Type | Required | Description |

**Endpoint:**

```http
DELETE /courses/{id}
```

**Description:**

Deletes a course owned by the authenticated instructor.

**Access:** INSTRUCTOR.

**Path Parameters:**

| Parameter | Type | Required | Description |
|---|---|---|---|
| `id` | UUID | Yes | Course identifier. |

**Success Response:**

`204 No Content`

No response body is returned.

**Possible Errors:**

- `401 Unauthorized` — Authentication is required.
- `403 Forbidden` — User does not own this course or does not have the INSTRUCTOR role.
- `404 Not Found` — Course does not exist.

Enrollment operations allow instructors to manage student participation in their own courses.

#### 4.4.1. Add a Student to a Course

**Endpoint:**

```http
POST /courses/{courseId}/students/{studentId}
```

**Description:**

Adds a specific student to a course owned by the authenticated instructor.

The specified user must have the `STUDENT` role.

**Access:** INSTRUCTOR.

**Path Parameters:**

| Parameter | Type | Required | Description |
|---|---|---|---|
| `courseId` | UUID | Yes | Course identifier. |
| `studentId` | UUID | Yes | Student identifier. |

**Request Body:**

No request body is required.

**Success Response:**

`201 Created`

```json
{
  "studentId": "33333333-3333-3333-3333-333333333333",
  "courseId": "22222222-2222-2222-2222-222222222222"
}
```

**Possible Errors:**

- `401 Unauthorized` — Authentication is required.
- `403 Forbidden` — User does not own this course or does not have the INSTRUCTOR role.
- `404 Not Found` — Course or student does not exist.


**Description:**

| Parameter | Type | Required | Description |

`200 OK`

**Endpoint:**

```http
DELETE /courses/{courseId}/students/{studentId}
```

**Description:**

Removes a student from a course owned by the authenticated instructor.

Only the enrollment relationship is deleted. The student account and course remain unchanged.

**Access:** INSTRUCTOR.

**Path Parameters:**

| Parameter | Type | Required | Description |
|---|---|---|---|
| `courseId` | UUID | Yes | Course identifier. |
| `studentId` | UUID | Yes | Student identifier. |

**Success Response:**

`204 No Content`

No response body is returned.

**Possible Errors:**

- `401 Unauthorized` — Authentication is required.
- `403 Forbidden` — User does not own this course or does not have the INSTRUCTOR role.

## 5. Error Handling

The API uses standard HTTP status codes to indicate the result of each request.

### 5.1. HTTP Status Codes

| Status Code | Name | Description |
|---|---|---|
| `200` | OK | Request completed successfully. |
| `201` | Created | A new resource was created successfully. |
| `204` | No Content | Request completed successfully without a response body. |
| `400` | Bad Request | Request data is invalid or incomplete. |
| `401` | Unauthorized | Authentication is required or the access token is invalid. |
| `403` | Forbidden | The authenticated user does not have permission to perform the operation. |
| `404` | Not Found | The requested resource does not exist. |
| `409` | Conflict | The request conflicts with existing data. |
| `500` | Internal Server Error | An unexpected server error occurred. |

### 5.2. Error Response Format

All error responses use the same JSON structure.

| Field | Type | Description |
|---|---|---|
| `status` | integer | HTTP status code. |
| `error` | string | Short error description. |
| `message` | string | Detailed error message. |
| `path` | string | API endpoint where the error occurred. |

**Example:**

```json
{
  "status": 404,
  "error": "Not Found",
  "message": "Course not found.",
  "path": "/api/v1/courses/22222222-2222-2222-2222-222222222222"
}
```

## 6. Business Rules and Constraints

The API follows the following business rules:

1. Every user must have a unique identifier generated by the server.
2. Every user must have a unique email address.
3. A user must have exactly one role: `INSTRUCTOR` or `STUDENT`.
4. The user's registration date is generated by the server.
5. Passwords are stored as secure hashes and are never returned in API responses.
6. Only authenticated users can access protected endpoints.
7. Only users with the `INSTRUCTOR` role can create, update, and delete courses.
8. An instructor can manage only courses created by that instructor.
9. The `instructorId` of a course is assigned automatically based on the authenticated user.
10. A course must have a title and a duration greater than zero.
11. Only users with the `STUDENT` role can be enrolled in courses.
12. Only the instructor who owns a course can add or remove students from it.
13. A student cannot be enrolled in the same course more than once.
14. Students cannot manage their own enrollment records.
15. A student can view only their own enrolled courses.
16. An instructor can view only students enrolled in their own courses.
17. Removing a student from a course deletes only the enrollment record. The student account and course remain unchanged.
18. Deleting a course also deletes all associated enrollment records. Student accounts remain unchanged.
19. If a course has no enrolled students, the corresponding endpoint returns an empty array.
20. If a student is not enrolled in any courses, their enrolled courses endpoint returns an empty array.
21. Successful DELETE operations return `204 No Content` without a response body.

## 7. API Design Conventions

The API follows these conventions:

- REST architectural principles are used for resource management.
- JSON is used as the request and response format.
- All endpoints use the `/api/v1` base path.
- Resource names are plural: `users`, `courses`, and `students`.
- UUID is used for resource identifiers.
- HTTP methods define the type of operation:
    - `GET` — retrieve resources.
    - `POST` — create resources.
    - `PUT` — update existing resources.
    - `DELETE` — delete resources.
- Resource identifiers are generated by the server.
- Authentication is implemented using JWT Bearer tokens.
- Authorization is based on user roles and resource ownership.
- Standard HTTP status codes are used to indicate operation results.
- Error responses follow a consistent JSON structure.
